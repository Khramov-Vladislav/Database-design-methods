\subsubsection{Создание представления}
% Для каждого студента подсчитать количество поселений и количество выполненных платежей. 

Для каждого студента найти идентификатор, фамилию, имя, отчество, количество поселений и количество выполненных платежей. 

Код представления приведен в листинге~\ref{lst:create-view}. Графическое представление запроса приведено на рисунке~\ref{fig:view_create_diagram}. 

Время выполнения запроса: 19.849 мс.

\begin{lstlisting} [
    language=SQL,
    caption={Создание представления},
    label={lst:create-view}
]
CREATE VIEW student_settlement_payment_counts AS
SELECT
    student.student_id,
    student.last_name,
    student.first_name,
    student.middle_name,
    COUNT(DISTINCT settlement.settlement_id) AS settlement_count,
    COUNT(DISTINCT payment.payment_id) AS payment_count
FROM
    student
    LEFT JOIN settlement ON student.student_id = settlement.student_id
    LEFT JOIN payment ON settlement.settlement_id = payment.settlement_id
GROUP BY
    student.student_id,
    student.last_name,
    student.first_name,
    student.middle_name;
\end{lstlisting}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.45\textwidth]{figures/view_create_diagram.png}
    \caption{Графическое представление создания представления}
    \label{fig:view_create_diagram}
\end{figure}

Выполнение запроса начинается в блоке \textbf{\texttt{FROM}}, где на основе базовой таблицы \texttt{student} через последовательные операторы \textbf{\texttt{LEFT JOIN}} формируется объединенный массив строк с таблицами \texttt{settlement} и \texttt{payment}, сохраняющий всех студентов даже при отсутствии связанных записей. Затем в блоке \textbf{\texttt{GROUP BY}} полученный набор данных разделяется на изолированные группы по уникальному сочетанию идентификатора и ФИО каждого студента. Далее в блоке \textbf{\texttt{SELECT}} внутри каждой группы вычисляются агрегатные функции \textbf{\texttt{COUNT(DISTINCT ...)}}, которые подсчитывают точное количество уникальных ID заселений (\texttt{settlement\_count}) и платежей (\texttt{payment\_count}), предотвращая дублирование результатов. На финальном этапе команда \textbf{\texttt{CREATE VIEW}} регистрирует этот алгоритм в базе данных под именем \textbf{\texttt{student\_settlement\_payment\_counts}}, создавая виртуальную таблицу, которая будет динамически выполнять всю описанную цепочку шагов при каждом обращении к ней.

\subsubsection{Запрос №1}
% Найти студентов, у которых количество выполненных платежей меньше, чем у студента «А». 

Найти студентов, у которых количество выполненных платежей меньше, чем у студента с фамилией «Glover», именем «Nels» и отчеством «Aimee», с указанием количества поселений и выполненных платежей.

Код запроса представлен в листинге~\ref{lst:view-query1}. Результирующая таблица представлена в таблице~\ref{tab:view-query1}. В результирующей таблице было выведено 4462 строк. Графическое представление запроса приведено на рисунке~\ref{fig:view_query1} и рисунке~\ref{fig:view_query1_diagram}. 

Время выполнения запроса: 247.327 мс.

\begin{lstlisting} [
    language=SQL,
    caption={Простой запрос к представлению},
    label={lst:view-query1}
]
SELECT
    student_settlement_payment_counts.last_name,
    student_settlement_payment_counts.first_name,
    student_settlement_payment_counts.middle_name,
    student_settlement_payment_counts.settlement_count,
    student_settlement_payment_counts.payment_count
FROM
    student_settlement_payment_counts
WHERE
    student_settlement_payment_counts.payment_count < (
        SELECT
            payment_count
        FROM
            student_settlement_payment_counts
        WHERE
            last_name = 'Glover'
            AND first_name = 'Nels'
            AND middle_name = 'Aimee'
    )
ORDER BY
    settlement_count DESC,
    payment_count DESC;
\end{lstlisting}

Выполнение запроса начинается с обращения к таблице \\student\_settlement\_payment\_counts, после чего СУБД изолированно запускает вложенный подзапрос, чтобы найти конкретное число оплат \\(payment\_count) для студента с ФИО "Glover Nels Aimee". Полученное значение используется во внешнем фильтре WHERE, который сканирует основную таблицу и оставляет только тех студентов, чьё количество оплат строго меньше этого числа. Затем в блоке SELECT для прошедших фильтрацию строк формируется итоговый набор колонок (ФИО, количество заселений и оплат), который на финальном этапе в блоке ORDER BY сортируется по убыванию количества заселений (settlement\_count DESC), а при их равенстве — дополнительно упорядочивается по убыванию количества оплат (payment\_count DESC).

% реляционная формула запроса
Реляционная формула запроса:
\begin{align*}
\text{Result} = {} & \tau_{\mathit{settlement\_count}\text{ DESC}, \mathit{payment\_count}\text{ DESC}} \Biggl( \\
& \pi_{\mathit{last\_name}, \mathit{first\_name}, \mathit{middle\_name}, \mathit{settlement\_count}, \mathit{payment\_count}} \Biggl( \\
& \sigma_{\mathit{payment\_count} < \mathit{ref\_payment\_count}} \left( S \times R_2 \right) \Biggr) \Biggr) \\[1.5ex]
\text{где } R_2 = {} & \rho_{\mathit{ref\_payment\_count} \leftarrow \mathit{payment\_count}}\left(\pi_{\mathit{payment\_count}}\left(\sigma_{\mathit{last\_name}=\text{'Glover'} \wedge \dots}(S)\right)\right)
\end{align*}

Для каждого студента найти фамилию, имя, отчество, количество поселений, количество выполненных платежей и количество оставленных отзывов.

Код запроса представлен в листинге~\ref{lst:view-query2}. Результирующая таблица представлена в таблице~\ref{tab:view-query2}. В результирующей таблице было выведено 5000 строк. \begin{lstlisting} [
    language=SQL,

SELECT
    student_settlement_payment_counts.last_name,
    student_settlement_payment_counts.first_name,
    student_settlement_payment_counts.middle_name,
    student_settlement_payment_counts.settlement_count,

    student_settlement_payment_counts.student_id,
    student_settlement_payment_counts.last_name,
    student_settlement_payment_counts.first_name,

% объяснение запроса 
Выполнение этого запроса начинается в блоке FROM, где СУБД берет таблицу student\_settlement\_payment\_counts и последовательно объединяет ее с помощью левого внешнего соединения (LEFT JOIN) сначала с таблицей settlement по идентификатору студента, а затем с таблицей review по идентификатору заселения, сохраняя при этом всех студентов, даже если у них нет заселений или отзывов. Далее данные группируются в блоке GROUP BY по уникальному идентификатору студента и всем запрашиваемым анкетным полям, чтобы объединить дублирующиеся из-за соединений строки. На этапе группировки в блоке SELECT рассчитывается агрегатная функция COUNT(DISTINCT...), которая подсчитывает точное количество уникальных отзывов для каждого студента, после чего формируется финальный набор данных, содержащий ФИО, количество заселений, количество оплат и вычисленное количество отзывов.

% реляционная формула запроса
Реляционная формула запроса:
\begin{align*}
\text{Result} = {} & \pi_{\mathit{last\_name}, \mathit{first\_name}, \mathit{middle\_name}, \mathit{settlement\_count}, \mathit{payment\_count}, \mathit{review\_count}} \Biggl( \\
& {}_{\mathit{student\_id}, \dots} \, \gamma_{\mathit{COUNT\_DISTINCT}(\mathit{review\_id}) \rightarrow \mathit{review\_count}} \Bigl( \\
& \big( S \mathbin{\bowtie\mkern-11.5mu\ltimes} \text{settlement} \big) \mathbin{\bowtie\mkern-11.5mu\ltimes} \text{review} \Bigr) \Biggr)
\end{align*}
